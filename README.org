* (Nix) Utilities for Mac App launchers

This is a [[https://nixos.org][Nix]] module for Macintosh computers (“darwin”) which fixes a few common problems encountered by users of Nix on Macs:

- Launching .app programs from Spotlight
- Pinning a .app in the Dock, even across Nix updates
- Keeping privacy permissions (e.g. Full Disk Access) granted to an app across Nix updates

Now you can launch Nix-installed apps using only your keyboard, using @@html:<kbd>@@⌘ space@@html:</kbd>@@.

** How to use

It works in [[https://github.com/nix-community/home-manager][home-manager]] and [[https://github.com/LnL7/nix-darwin][nix-darwin]] by providing a module for both.  You just need to load the module, nothing else, and it will automatically run every time you =switch= your config.

Home-manager and nix-darwin aren’t either-or: you can have both, and you can install .app bundles on your mac through both (some user specific using home-manager, some system wide using nix-darwin).  In that case you’d want to load both the nix-darwin module, and the home-manager module at the same time in their respective configurations.

*** The signing certificate

mac-app-util installs a /signed copy/ of each of your apps, so that macOS keeps recognizing them (and the permissions you gave them) after an update. See [[*Why copies, and why a certificate][below]] for why. That needs a code-signing certificate, and the modules set one up for you:

- The first time you =switch= with apps to install, the module creates a self-signed certificate: =mac-app-util user signing= in your login keychain (home-manager), or =mac-app-util system signing= in the System keychain (nix-darwin).
- macOS asks for your password once, to trust it. Run that first =switch= at your Mac, not over SSH: without someone to answer the prompt, the activation can't complete.
- After that it is reused, and activation is unattended. It is never created if there are no apps to sign.

Nothing needs configuring. To use a certificate of your own, set =signingIdentity= to its name or hash, and turn off automatic creation:

#+begin_src nix
# home-manager
targets.darwin.mac-app-util = {
  signingIdentity = "My Code Signing Certificate";
  createSigningIdentity = false;
};

# nix-darwin (the certificate must be in the System keychain)
services.mac-app-util = {
  signingIdentity = "My Code Signing Certificate";
  createSigningIdentity = false;
};
#+end_src

See [[*create-cert][=create-cert=]] to create one by hand.

*** Custom icons

Give an app a custom icon with the =icons= option, an attribute set from app name (=Emacs= for =Emacs.app=) to a directory:

#+begin_src nix
# home-manager
targets.darwin.mac-app-util.icons.Emacs = "${inputs.emacs-icon}/Resources";

# nix-darwin
services.mac-app-util.icons.Emacs = "${inputs.emacs-icon}/Resources";
#+end_src

The directory must contain exactly one =.icns= file. It may also contain a compiled =Assets.car=, which gives the Liquid Glass icon on macOS 26 and later; the icon in it must have the same name as the =.icns= file (=Emacs.icns= and an icon named =Emacs=). Both are applied to the signed copy of the app, so the icon is kept across updates. If the app has an =Assets.car= of its own it is left alone (it holds more than the icon), and only the =.icns= is used.

Finder and the Dock cache icons; if the old one still shows after a =switch=, run =killall Dock Finder=.

*** Flakes, just home-manager

Only using home-manager, no nix-darwin (yet)? You can import the home-manager module directly:

#+begin_src nix
{
  description = "Minimal Flake for macOS with home-manager and mac-app-util";

  inputs = {
    mac-app-util.url = "github:hraban/mac-app-util";
  };

  outputs = { self, nixpkgs, home-manager, mac-app-util, ... }: let
    username = "jdoe";
    system = "aarch64-darwin";
  in {
    homeConfigurations.${username} = home-manager.lib.homeManagerConfiguration {
      pkgs = import nixpkgs { inherit system; config.allowUnfree = true; };
      modules = [
        mac-app-util.homeManagerModules.default
        ({ pkgs, ... }: {
          home = {
            inherit username;
            homeDirectory = "/Users/${username}";
            # This is where you would install any programs as usual:
            packages = with pkgs; [
              ripgrep
              vim

              # What mac-app-util does for you, is that you can also just
              # install derivations here which have a `/Applications/`
              # directory, and it will be available in Spotlight and in your App
              # Launcher, no further configuration needed:
              vscode
              iterm2
            ];
            stateVersion = "24.05";
          };
        })
      ];
    };
  };
}
#+end_src

*** Flakes, nix-darwin (with or without home-manager)

#+begin_src nix
{
  inputs = {
    #...
    mac-app-util.url = "github:hraban/mac-app-util";
    #...
  };

  outputs = {
    nix-darwin
    , home-manager
    , mac-app-util
    , ...
  }: {
    darwinConfigurations = {
      MyHost = nix-darwin.lib.darwinSystem {
        # ...

        modules = [
          mac-app-util.darwinModules.default

          # And if you also use home manager:
          home-manager.darwinModules.home-manager
          (
            { pkgs, config, inputs, ... }:
            {
              # To enable it for all users:
              home-manager.sharedModules = [
                mac-app-util.homeManagerModules.default
              ];

              # Or to enable it for a single user only:
              home-manager.users.foobar.imports = [
                #...
                mac-app-util.homeManagerModules.default
              ];
            }
          )

        ];
      };
    };
  };
}
#+end_src

*** Non-flakes, aka “channels”

This is similar to the above. What will be different is the “plumbing”, i.e. how to get a reference to this app’s derivation. Here’s how:

#+begin_src nix
let
  mac-app-util-src = builtins.fetchTarball "https://github.com/hraban/mac-app-util/archive/master.tar.gz";
  # I advise using the long form with a pinned hash instead
  mac-app-util-src = builtins.fetchTarball {
    url = "https://github.com/hraban/mac-app-util/archive/abcdef123456abcdef123456.tar.gz";
    # Run it once, lift the hash from the error, paste it here and run again
    sha256 = "";
  };
  mac-app-util = import mac-app-util-src {};
in

# Now you have either the program as a derivation itself:
mac-app-util.default

# Or the home manager module:
mac-app-util.homeManagerModules.default

# Or darwin:
mac-app-util.darwinModules.default
#+end_src

Example:

#+begin_src nix
{ config, pkgs, ... }:

let
  mac-app-util-src = builtins.fetchTarball "https://github.com/hraban/mac-app-util/archive/master.tar.gz";
  mac-app-util = import mac-app-util-src {};
in

{
  home = {
    username = "jdoe";
    homeDirectory = "/Users/jdoe";
    stateVersion = "24.05";
    packages = with pkgs; [
      iterm2
    ];
  };
  programs.home-manager.enable = true;
  imports = [
    mac-app-util.homeManagerModules.default
  ];
}
#+end_src

** Commands

At the core of this project is a (Nix-agnostic) program that can:

- =sync-dock= :: Update persistent apps in the Dock
- =create-cert= :: Create a self-signed code-signing certificate
- =sign-copy= :: Copy an app and sign the copy with a code-signing certificate
- =sync-trampolines= :: Create a directory with signed copies of all your apps (this is what the modules run)

** sync-dock

When you have an app in your Dock which doesn’t live in =/Applications/..=, it can get stale: e.g. your app at =/foo/v1/Foo.app= gets replaced by =/foo/v2/Foo.app=. To automatically update the Dock to the new location of Foo, execute:

#+begin_src shell
$ nix run github:hraban/mac-app-util -- sync-dock Foo.app
#+end_src

It will find an old persistent item by the name of "Foo" and update it to the new location.

N.B.: This is currently limited only to Nix apps, but actually it could work for anything. I’ve just kept it conservative to be on the safe side.

** create-cert

Creates a self-signed code-signing certificate. The modules do this for you (see [[*The signing certificate][The signing certificate]]); run it by hand if you turned that off, or to set things up ahead of time:

#+begin_src shell
$ nix run github:hraban/mac-app-util -- create-cert            # in your login keychain
$ sudo nix run github:hraban/mac-app-util -- create-cert       # as root: in the System keychain, for nix-darwin
$ nix run github:hraban/mac-app-util -- create-cert "My Cert"  # or pick a name
#+end_src

The default name is =mac-app-util user signing=, or =mac-app-util system signing= when run as root, matching the modules' defaults. The two names differ on purpose: users can see the System keychain too, and with a shared name a user could pick up the system certificate, whose private key they cannot use.

It generates a key and certificate with =openssl=, imports them into the keychain, and trusts the certificate for code signing. Trusting it asks for a password. It does nothing if an identity with that name already exists. The private key only lives in a temporary directory and the keychain, never in the Nix store.

The first time =codesign= uses the key, macOS may ask for permission; choose "Always Allow". To avoid that prompt, run once, as the command's output also says:

#+begin_src shell
$ security set-key-partition-list -S apple-tool:,apple:,codesign: -s ~/Library/Keychains/login.keychain-db
#+end_src

Identities are matched by their exact name, or by their SHA-1 hash, and apps are signed by hash. If several certificates have the same name, signing fails and asks you to remove the extras; see them with =security find-identity -p codesigning=, and delete one with =security delete-identity -Z <hash>=.

You can also create the certificate by hand: Keychain Access → Certificate Assistant → Create a Certificate…, with /Certificate Type/ set to /Code Signing/.

** sign-copy

#+begin_src shell
$ nix run github:hraban/mac-app-util -- sign-copy /path/to/MyApp.app /Applications/MyApp.app "My Signing Certificate"
#+end_src

Copies the app bundle and signs the copy with the named code-signing identity.

With a fourth argument, a directory as described in [[*Custom icons][Custom icons]], the copy gets that icon before it is signed:

#+begin_src shell
$ nix run github:hraban/mac-app-util -- sign-copy /path/to/Emacs.app /Applications/Emacs.app "My Signing Certificate" /path/to/Resources
#+end_src

** sync-trampolines

Combines =sign-copy= and =sync-dock= to create a fresh directory with a signed copy of every source app. E.g.:

#+begin_src shell
$ nix run github:hraban/mac-app-util -- sync-trampolines ~/special/apps/ ~/Applications/Special/
#+end_src

Will create a fresh directory (=~/Applications/Special=), deleting if it already existed. In that directory it will put a signed copy of every single =*.app= file it finds in =~/special/apps/=.

It signs with the certificate named in =MAC_APP_UTIL_SIGN_IDENTITY=, or with the [[*create-cert][=create-cert=]] default if that is unset. If the certificate is missing it fails, pointing to =create-cert=; with =MAC_APP_UTIL_CREATE_CERT=1= it creates the certificate instead, as the modules do. Either way it only touches the keychain when there are apps to sign.

Every app =Foo.app= for which the directory in =MAC_APP_UTIL_ICONS_DIR= has a subdirectory =Foo= gets the icon in that subdirectory (the modules set this up from their =icons= option).

This helps register apps from outside of your =~/Applications= directory with Spotlight and the Launchpad.

The name is historical: the apps are real copies, not trampolines.

The modules run it for you on every activation: home-manager copies =~/Applications/Home Manager Apps= to =~/Applications/Home Manager Trampolines=, and nix-darwin copies =/Applications/Nix Apps= to =/Applications/Nix Trampolines=. (The directory names are historical too.)

*** Why copies, and why a certificate

Privacy permissions such as Full Disk Access are granted to the app that actually runs, and macOS identifies it by its code signature. Apps built by Nix are only ad-hoc signed, so their identity is a hash of the code that changes with every build. After each update macOS no longer recognizes the app and drops the grant. A launcher app in front of the real app cannot help: the grant belongs to the launched app, not the launcher.

Signing the copy with a fixed certificate makes its identity "this bundle ID, signed by this certificate", which stays the same across updates. You grant Full Disk Access once to the copy, and it persists.

*** Caveats

- The copy is signed anew, so the original signature (and with it any notarization) is gone. Entitlements, flags and runtime options are preserved.
- Symlinks that point outside the app bundle (common with Nix) are replaced by copies of their targets, so the copies take more disk space.
- Every run replaces the copies; the Dock is pointed at them.
- Apple's own apps cannot be signed this way: a signed copy of TextEdit fails to launch ("Launchd job spawn failed"), most likely because Apple's apps carry entitlements that only Apple's signature is allowed to have. This doesn't affect apps installed through Nix, and there is no reason to copy Apple's apps anyway, but keep it in mind if you point =sign-copy= at one.

** Testing

=tests/e2e-fda.sh= is an end-to-end test of the main feature: that a Full Disk Access grant survives an app update. Run it by hand on a Mac, from a terminal, in a checkout of this repo:

#+begin_src shell
$ ./tests/e2e-fda.sh
#+end_src

It builds two versions of a tiny test app (=nix build .#test-app=, and =.#test-app-v2= standing in for an update), installs v1 as a signed copy with =sync-trampolines=, and checks it is denied access. You then grant Full Disk Access to the copy in System Settings (the one manual step; macOS does not allow scripting it), and the script checks that access works, replaces v1 with v2, and checks that access still works without a new grant. The test app's permission entry is reset at the start and end, and everything else lives in a temporary directory.
